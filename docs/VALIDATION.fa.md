## ایرادهایی که حین آزمون اصلاح شدند

- MIME آرشیو upload به application/gzip اصلاح شد.
- آماده‌شدن release پیش از پایان rollout مشاهده شد؛ probe خواندنی با انتظار محدود اضافه شد. بررسی مجدد انتشار فقط در صورت تطبیق release فعال مجاز است و انتشار جدید نمی‌سازد.
- قطع شبکه و تأخیر وضعیت GitHub مشاهده شد. checkpoint شاخه و SHA حفظ می‌شود، شکست job می‌تواند زودتر انتشار را مسدود کند؛ موفقیت فقط با workflow کاملِ موفق پذیرفته می‌شود.
- نتیجه CI موفق برای همان پروژه، مخزن و commit ذخیره می‌شود. تغییر هرکدام مجوز قبلی را معتبر نمی‌کند؛ diff و تأیید انتشار همچنان جدا هستند.
- مدل در دو تلاش پاسخ ناقص/غیر JSON داد؛ پاسخ رد شد و هیچ کدی اجرا نشد. سقف خروجی اصلاح افزایش یافت و پیام خطا روشن شد.
- تست‌های پذیرش ثابت و پیشنهاد ناموفق قبلی به مدل اصلاح داده می‌شود؛ مدل حق تغییر تست، dependency یا workflow ندارد.
- شواهد خلاصه می‌شوند تا لاگ قدیمی، خطای درخواست فعلی را از ورودی مدل بیرون نکند. مدل باید نبود واحد متریک و تفاوت وضعیت فعلی و تاریخی را اعلام کند.
- در اجرای دوم تنظیمات، پس از مشاهدهٔ 500، probe تحلیل 200 دریافت کرد. تحلیل این اختلاف زمان/rollout را بیان کرد؛ این اجرا مدرک یک اختلال کاملاً ثابت در تمام درخواست‌ها نیست.

## آزمون‌های خودکار محلی

- آخرین اجرای ثبت‌شده: ۳۴ تست دستیار، ۶ تست نمونه و build در نصب مستقل موفق بودند. جزئیات زمانی در بخش‌های پایین این گزارش آمده است. اجرای build داخل sandbox به محدودیت دسترسی esbuild خورد؛ اجرای مجاز خارج sandbox موفق شد.
- اعتبارسنجی آرشیو و سقف حجم/فایل، حذف secret و root صحیح؛ archive traversal و symlink رد می‌شوند.
- تأیید منقضی، مصرف‌شده، ردشده یا مقصد تغییرکرده اجرا نمی‌شود؛ درخواست تکراری و اجرای هم‌زمان کنترل می‌شوند.
- exact-SHA CI، عدم پذیرش موفقیت ظاهری HTTP با مبلغ غلط، حفاظت SSRF و عدم ساخت قیمت/متریک بررسی شدند.
- SQLite پس از بازشدن مجدد تأیید مصرف‌شده را حفظ می‌کند؛ reconcile نتیجه همان commit را خواندنی بازیابی می‌کند و در خطای provider checkpoint را حذف نمی‌کند.
- سیاست سه شکست متوالی، فاصلهٔ ده دقیقه بین تحلیل‌ها و پایان خودکار بار محدود، با آزمون محلی بررسی شدند.

این آزمون‌ها جایگزین اجرای چندساعته پایش یا تست crash واقعیِ دستیار روی لیارا نیستند.

## محدودیت‌ها و کار باقی‌مانده

- خرید/ساخت سرویس جدید، resize، قرارداد مالیات و قیمت روی حساب تأیید نشده‌اند؛ آزمایش انتشار روی برنامهٔ از قبل موجود انجام شد.

- سناریوی کد یک چرخه کامل موفق دارد؛ دو تمرین کامل از همه سناریوها و ضبط ویدئو هنوز انجام نشده است.
- مخزن نمونه منتشر شده است؛ مخزن اصلی دستیار و مستندات هنوز push نشده‌اند.
- طبقه‌بندی سناریوی کندی توسط مدل code بود و به پردازش داخلی اشاره کرد؛ علت کمبود CPU/RAM را قطعی نکرد. عنوان سناریوی آزمایشی، جواب از پیش‌تعیین‌شدهٔ مدل نیست.
