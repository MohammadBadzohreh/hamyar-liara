# نتیجه بررسی حساب و آمادگی مسابقه

تاریخ: ۲۰۲۶-۱۰-۲۲. بررسی پنل واقعی و منابع رسمی انجام شده؛ درخواست API با توکن هنوز اجرا نشده است. هیچ سرویس، شبکه، کلید یا مجوز جدیدی ایجاد نشده. فرم ایجاد برنامه تا انتخاب منابع بررسی و بدون ثبت سفارش ترک شد؛ ممکن است پنل پیش‌نویس محلی فرم را حفظ کرده باشد.

## وضعیت مشاهده‌شده

- حساب در حالت تیمی و نقش کاربر «مالک» است. Team ID در صفحه `/API` قابل مشاهده است؛ در سند عمومی درج نشده.
- اعتبار مثبت و بخش پلتفرم، دیتابیس، DNS و پروژه‌های AI خالی است.
- اتصال حساب GitHub برقرار است؛ دامنه repositoryهای مجاز هنوز بررسی نشده.
- ورود دومرحله‌ای فعال است. پنل هشدار می‌دهد تغییر رمز عبور کلیدهای API و نشست‌های CLI را نامعتبر می‌کند.
- صفحه API انقضای ۱ ساعت، ۱ روز، ۷ روز، ۱ ماه، ۶ ماه و ۱ سال را ارائه می‌دهد. در فرم مشاهده‌شده گزینه محدودکردن scope وجود ندارد؛ این اثبات نبودن قابلیت در کل محصول نیست. توکن مالک نباید read-only فرض شود.
- نقش‌های تیم شامل بازرس (دیدن)، گرداننده (عملیات)، مدیر و مالک هستند. محدودسازی نقش کاربر با scope خود توکن یکسان نیست.
- در مرحله شبکه فرم ساخت برنامه، گزینه‌ای نمایش داده نشد؛ وضعیت قطعی شبکه با GET /v1/networks بررسی شود.
- آدرس موقت liara.run طبق متن پنل فقط تا ۷ روز پس از اولین استقرار فعال است. برای دموی دیرتر، دامنه لازم است یا زمان استقرار باید نزدیک ضبط باشد.

## پلن مشاهده‌شده، نه سفارش‌شده

در انتخاب NodeJS و بسته «پایه»:

| پلن | RAM | vCPU | Disk | ماهانه، تومان | ساعتی، تومان |
|---|---|---|---|---:|---:|
| زمین | 512 MB | 0.5 | 5 GB | 750,000 | 1,040 |
| مریخ | 1 GB | 1 | 10 GB | 1,300,000 | 1,804 |
| مشتری | 2 GB | 1 | 20 GB | 2,300,000 | 3,193 |

مالیات طبق پنل جدا اضافه می‌شود. تمام پلن‌های نمایش‌داده‌شده ایران بودند. قیمت باید پیش از اقدام دوباره دریافت شود. برای یک برنامه ساده آزمایشی Node.js، زمین نامزد اولیه است؛ کافی‌بودن آن برای خود agent یا build سنگین هنوز اثبات نشده. دو برنامه جدا یعنی دو هزینه؛ هزینه AI و دیتابیس جدا بررسی شود. قیمت ساعتی نمایش‌داده‌شده مبنای تخمین کوتاه‌مدت است، نه تضمین صورت‌حساب.

## یافته‌های تکمیلی API

| مسیر | کاربرد | سطح شواهد |
|---|---|---|
| GET /v1/me | plans و مشخصات حساب/تیم | مستندات رسمی |
| GET /v1/billing | موجودی اعتبار به تومان | مستندات رسمی |
| GET /v1/me/subscription | سطح کاربری | مستندات رسمی |
| GET /v1/me/git-integrations | اتصال حساب و repositoryهای Git | مستندات رسمی |
| GET /v1/me/utm | اطلاعات کمپین در صورت وجود | مستندات رسمی؛ ارتباط با اعتبار مسابقه تضمین نشده |
| GET /v1/me/free-credit | اعتبار رایگان شخصی | مستندات؛ فیلد در حالت تیمی وجود ندارد، جایگزین billing نیست |
| GET /v1/networks | شبکه‌های خصوصی | کد CLI رسمی |
| GET /v2/projects/{name}/logs | لاگ runtime | کد CLI رسمی؛ آزمایش‌نشده |
| GET /v2/releases/{releaseID}/build-logs | لاگ build | کد CLI رسمی؛ آزمایش‌نشده |

### نکات قرارداد

- CLI رسمی `teamID` را به query string اضافه می‌کند. هدر `Authorization: Bearer ...` است. مقصد تیم باید صریح باشد تا اعتبار یا سرویس حساب شخصی اشتباهاً استفاده نشود.
- `/v1/me` ممکن است اطلاعات هویتی و کلیدهای Object Storage را برگرداند. فقط plans و فیلدهای ضروری تیم با allowlist استخراج شوند؛ پاسخ خام وارد log، prompt یا Git نشود.
- پلن‌های منابع از `plans.projects` و بسته امکانات از `plans.projectBundlePlans` دریافت می‌شوند. فقط موارد available قابل سفارش‌اند.
- CLI هنگام ساخت برنامه علاوه بر planID، فیلد bundlePlanID می‌فرستد؛ schema فعلی OpenAPI آن را در Create-app ندارد. برنامه باید هر دو انتخاب را مدل کند.
- CLI لاگ v2 را با start (Unix seconds)، direction=forward، last_lines و releaseId اختیاری می‌خواند؛ پاسخ شامل data، metaData و values است. ترتیب گروه‌ها الزاماً ترتیب زمانی سراسری نیست؛ پس از ادغام مرتب شود.
- نگهداری لاگ در CLI از `maxLogsRetention` بسته امکانات، به روز، تعیین می‌شود. داده خارج از بازه نباید خطای برنامه تلقی شود.
- build-logs از releaseID و cursor زمانی since استفاده می‌کند. این مسیر با لاگ runtime متفاوت است.
- هیچ‌یک از مسیرهای فوق هنوز با توکن این حساب آزمایش نشده‌اند. مسیر v1 لاگ در OpenAPI موجود است اما انطباق با نسخه زنده باید سنجیده شود.

## داده‌های دقیق موردنیاز برای محصول

| بخش | داده لازم | منبع |
|---|---|---|
| اتصال | توکن با انقضا، teamID، نقش و مجوز | پنل API و me |
| بودجه | موجودی، قیمت منابع/بسته، مالیات، سقف هزینه مجاز | billing، plans، تأیید کاربر |
| شناسایی برنامه | نام، شناسه داخلی، پلتفرم، وضعیت، planID، bundlePlanID، network | projects و جزئیات برنامه |
| آماده‌سازی سورس | repo/branch/commit یا فایل، runtime، build/start، پورت، envهای لازم، health path | سورس و تنظیمات پروژه |
| انتشار | sourceID، releaseID، وضعیت build و release، زمان انتشار | sources/releases/build-logs |
| SRE | بازه خطا، HTTP status/latency، لاگ، رویداد، CPU/RAM، آخرین release | probe محدود و API |
| دامنه | دامنه واقعی، zone، رکورد لازم، وضعیت SSL، دسترسی ثبت‌کننده | کاربر، DNS و domains |
| اصلاح | diff یا تغییر config، ریسک، تأیید مربوط به همان پارامترها، وضعیت قبل/بعد | backend workflow و audit log |
| مدل | ارائه‌دهنده، کلید مستقل AI، base URL، model، هزینه و tool-calling | سرویس مدل منتخب |

کلید زیرساخت با کلید مدل هوش مصنوعی متفاوت است. در لیارا AI باید پروژه و کلید با دسترسی پروژه ساخته شود؛ هیچ‌کدام در این حساب آماده نیست. انتخاب مدل و پوشش اعتبار مسابقه باید پیش از مصرف روشن شود.

## آزمایش‌های بعدی، به ترتیب

1. ساخت کلید کوتاه‌عمر با تأیید مشخص و نگهداری محلی خارج از Git؛ پیشنهاد برای بررسی اولیه: ۱ روز.
2. درخواست خواندنی me و billing و networks با teamID؛ خروجی صرفاً فیلدهای مجاز و وضعیت موفقیت.
3. اعتبارسنجی plans: شناسه واقعی منابع/بسته، قیمت، available، سقف انتشار و نگهداری لاگ؛ هیچ ID از نام فارسی حدس زده نشود.
4. بررسی اتصال repository با endpoint خواندنی؛ اتصال OAuth جدید برای بررسی اولیه لازم نیست.
5. ارائه پیشنهاد ساخت یک برنامه آزمایشی با قیمت، بازه استفاده و سقف هزینه؛ پس از تأیید، ساخت و انتشار نمونه.
6. آزمایش log v2، build logs، CPU/RAM، events؛ تعیین واحدها و رفتار پاسخ خالی و خطا.
7. بازتولید ۵۰۰ در نمونه، تشخیص از شواهد واقعی، اصلاح با تأیید و probe نتیجه.

## موارد حل‌نشده

- زمان انقضا و خدمات مجاز اعتبار مسابقه در صفحات بررسی‌شده مشخص نشد؛ موجودی مثبت، پاسخ این دو سؤال نیست.
- هنوز endpoint قابل اتکا برای rollback مستقیم یا trigger خودکار حادثه تأیید نشده.
- واحد و نرمال‌سازی CPU/RAM، تأخیر metrics، rate limit و رفتار polling به تست واقعی نیاز دارند.
- merge یا replace بودن update-envs باید پیش از اصلاح بررسی شود تا envهای موجود حذف نشوند.
- GitHub account متصل است؛ دسترسی repo و روش deployment خودکار آن باید برای repo منتخب بررسی شود.
- برای تغییر nameserver در ایرنیک به مسیر جدا از API لیارا نیاز داریم.
