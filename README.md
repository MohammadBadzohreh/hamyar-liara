# همیار لیارا

وب‌اپ فارسی تک‌مالک برای بررسی پروژه Node.js، پیشنهاد زیرساخت، انتشار با تأیید، جمع‌آوری شواهد و پیشنهاد اصلاح کد یا تنظیمات.

**وضعیت:** نسخه محلی قابل‌اجراست؛ اتصال واقعی لیارا و AI، انتشار [سایت نمونه](https://sample-node-app.liara.run)، رفع خطای تنظیمات، رد patch ناقص، اصلاح کد با GitHub Actions، انتشار همان commit، کندی کنترل‌شده، ری‌استارت و بازیابی آزمایش شده‌اند. استقرار آنلاین خود دستیار، بازبینی بصری و ویدئوی مسابقه هنوز تکمیل نشده‌اند. جزئیات شواهد در `docs/VALIDATION.fa.md` آمده است؛ داده دریافت‌نشده «نامشخص» نمایش داده می‌شود.

## اجرای محلی

نیازمند Node.js 24 و npm:

```sh
git clone https://github.com/MohammadBadzohreh/hamyar-liara.git
cd hamyar-liara
npm ci
npm run setup
npm run build
npm start
```

مخزن تحویل فعلاً خصوصی است؛ برای clone و ارزیابی، دسترسی GitHub مالک یا داور لازم است. کلیدهای سرویس و داده‌های حساب در مخزن قرار ندارند.

آدرس: http://127.0.0.1:3000 . رمز مالک در `.local/owner-login.txt` ساخته می‌شود؛ در چت و خروجی terminal چاپ نمی‌شود. `setup` فایل `.env` موجود را بازنویسی نمی‌کند. برای توسعه، `npm run dev` و `npm run dev:ui` را در دو ترمینال اجرا کنید.

## اتصال

کلیدها فقط در `.env` سرور قرار می‌گیرند؛ بعد از تغییر، سرور restart شود.

| متغیر | کاربرد |
|---|---|
| `LIARA_API_TOKEN`, `LIARA_TEAM_ID` | Bearer و تیم صریح درخواست‌های لیارا |
| `AI_BASE_URL`, `AI_API_KEY` | URL پروژه Liara AI و کلید مدل |
| `GITHUB_TOKEN` | توکن محدود به مخزن نمونه؛ Contents read/write و Actions read |
| `REPAIR_REPOSITORY` | نام دقیق `owner/repository` مخزن مستقل نمونه |
| `OWNER_PASSWORD_HASH`, `ENCRYPTION_KEY` | هش ورود و کلید رمزگذاری؛ توسط setup ساخته می‌شوند |
| `DEMO_TOKEN` | مجوز سناریوی نمونه؛ همان مقدار در نمونه، بدون کلید زیرساخت |

در نصب جدید، قرارداد قیمت، مالیات، موجودی و رفتار env باید بررسی شود. در حساب آزمایش، ارسال فهرست کامل env و حفظ مقادیر با خواندن مجدد تأیید شده و `LIARA_ENV_UPDATE_MODE=full-list-verified` فعال است؛ از این نتیجه معنای حذف یا merge استنتاج نمی‌شود. قیمت و مالیات هنوز برای خرید تأیید نشده‌اند. هیچ قیمت، موجودی یا نمودار ساختگی جایگزین خطای API نمی‌شود.

## استفاده

۱. وارد شوید و مخزن، شاخه، شناسه برنامه لیارا و پورت را معرفی کنید.
۲. سورس را بررسی کنید. شاخه به commit SHA مشخص تبدیل و آرشیو اعتبارسنجی می‌شود.
۳. پلن‌ها را از حساب دریافت کنید؛ پیشنهاد کم‌هزینه برای شروع آزمون، تخمین تضمینی ظرفیت نیست.
۴. پیشنهاد انتشار را ببینید و همان مقصد و تغییر را تأیید کنید. مراحل و شناسه انتشار در تاریخچه می‌مانند.
۵. در عیب‌یابی، مسیر مشکل را انتخاب کنید. لاگ، HTTP و منابع جمع‌آوری می‌شوند؛ نبود مدل مانع دیدن شواهد نیست.
۶. تغییر env تأیید جدا دارد. اصلاح کد فقط برای checkout مخزن نمونه است؛ ابتدا diff، ساخت شاخه و تست، سپس تأیید مستقل انتشار همان commit.

## آزمون و نمونه

```sh
npm test
npm run test:sample
node scripts/prepare-sample.mjs healthy
node scripts/prepare-sample.mjs buggy
```

کپی‌های نمونه در `.local` ساخته می‌شوند. هیچ مخزن ریموتی خودکار ساخته نمی‌شود. محتویات `sample/` باید در ریشه مخزن جدا باشند. workflow ثابت `.github/workflows/acceptance.yml` پیش از اصلاح باید روی شاخه اصلی موجود باشد. تست خروجی مدل فقط در GitHub اجرا می‌شود؛ کندی CI اجازه دورزدن تست نمی‌دهد.

اجرای محلی فروشگاه: متغیر `DEMO_PAYMENT_MODE=sandbox` را در محیط همان فرایند تنظیم و `npm run sample` را اجرا کنید؛ پورت پیش‌فرض 3100 است. فایل `.env` دستیار به نمونه بارگذاری نمی‌شود.

برای تهیه بسته سورس بدون فایل‌های محلی، `node scripts/package-delivery.mjs` را اجرا کنید. خروجی و فهرست checksum در `.local/delivery` ساخته می‌شوند. ابزار حضور مقادیر کلیدهای تنظیم‌شده و سرآیند کلید خصوصی را بررسی می‌کند؛ جای بازبینی جامع secretها نیست. این بسته، انتشار در GitHub یا تحویل ویدئو محسوب نمی‌شود.

برای نگهداری workflow، فرمان اختیاری `scripts/repair-ci-registration.mjs --reset` به مجوز اضافی Actions write نیاز دارد. مسیر عادی مشاهده تست‌ها همان Actions read را نیاز دارد؛ مجوز نوشتن GITHUB_TOKEN داخل runner لازم نیست.

Dockerfile برای انتشار دستیار با Node 24 آماده است؛ اجرای Docker در این محیط آزمایش نشده. نسخه آنلاین تک‌نمونه، HTTPS و دیسک پایدار `data` روی `/app/data` لازم دارد. هزینه سرویس باید پیش از ساخت تأیید شود. نسخه محلی پشتیبان ضبط است، نه مدرک انتشار آنلاین.
